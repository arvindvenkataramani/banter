# Voice settings: build spec

Implements [`dev/design/voice-settings.md`](../design/voice-settings.md). The plugin parts amend [`dsh-voice-plugin.md`](dsh-voice-plugin.md), whose sections 2, 4, 7, 8 and 10 point here for settings.

## 1. Control plane

- `VoiceSelectionPatch.vad` and `.turnTaking` fields take `number | null`, in `control/control-plane/src/gateway-config.ts`, the route schema in `routes.ts` (each field `.nullable().optional()`), and the engine's copy of the type in `voice-engine/src/voice-config.ts`.
- Validation: `null` passes; a number is checked as now; an unknown field is refused whatever its value.
- Merge: a `null` field is deleted from its section; other fields merge by key; the section object stays, `{}` when emptied.
- Commit check: min and max are the values that stand after the patch; a field sent as `null` counts as absent, not as its stored value.
- The OpenAPI descriptions say that `null` removes a field so the engine's default applies. `docs/reference/api.md` is regenerated by the pre-commit hook.

## 2. Dashboard

### `dashboard/src/features/settings/voice-settings-model.ts`

Pure; the plugin's former `settings-model.ts`, re-targeted at the voice config and the control plane's patch.

- `TUNING_FIELDS`: the plugin's table as it stands (key, section, label, unit, step, min, max, `default`, description).
- `Draft`: `config` (the `VoiceConfig` seeded from; never changes), `sttServiceId`, `ttsServiceId`, `ttsModel`, `ttsVoice`, `ttsSpeed`, `takeover`, `saveMicSamples`, `scope`, `global`, `prefs`, `touched`, `tuning`.
- `seedDraft(config, selection: VoiceSelection) → Draft`. `takeover` defaults to `'ask'`, `saveMicSamples` to `false`.
- Edits, each `(draft, …) → Draft`: `setProvider`, `setModel`, `setVoice`, `setSpeed`, `setSttService`, `setTakeover`, `setSaveMicSamples`, `setScope`, `editChunking`, `resetChunking`, `setTuning`, `resetTuning`. Cascades as the plugin's.
- `roster(draft)`, `chunkingView(draft)`: as the plugin's.
- `buildPatch(draft) → VoiceSelectionPatch | null`. `null` when nothing differs from `draft.config`. Otherwise: `serviceId`, `model`, `voice`, `speed` always; `sttServiceId`, `takeover`, `saveMicSamples`, `settingsScope` when changed; the global chunk options from `diffGlobalOptions` when non-empty; `modelPrefs` holding exactly the touched models' entries (`buildModelPrefEntry`, `null` for an empty one); `vad` and `turnTaking` holding each changed field with its value, and `null` for a field stored in the config and reset in the draft. A field neither stored nor set is never sent.

### `voice-settings.tsx`, `settings-dialog.tsx`

- `useVoiceSettings(open)` returns `{ status, speech, listening, general, help, save }`. State is one `Draft`, seeded once per open as now. `save()` sends `buildPatch`'s body through `updateVoiceSelection`, does nothing for `null`, unloads the old TTS model when the model changed, and applies the result with `applySavedVoiceSettings` and `setSaveMicSamples` as now.
- Content and wording are the plugin page's as it stood before this change (`plugins/dsh/voice/src/client/settings-card.tsx` at the commit before), in shadcn components: `Select`, `Slider`, `RadioGroup`, `Switch`, `Input`, `Button`, `Badge` with `Tooltip`, `Tabs`. Doc links point at the repository docs, as in the plugin, opening in a new tab. *General* holds "Always take over" (when the selected services declare sessions) and "Save mic samples to disk", with the plugin's take-over wording and Banter's samples wording. *Help* drops the plugin-docs link. The Banter server URL and keep-voice-outside are not in Banter.
- Tabs in the order Speech, Listening, General, Help; Speech selected on open. Footer, page security notice and outside-click guard as now.
- No custom CSS: Tailwind utilities and shadcn components only.

### Opening from a link

`nav-bar.tsx`: when the page loads with a `settings` query parameter, the dialog opens and the parameter is removed with `history.replaceState`, keeping the rest of the URL.

## 3. dsh plugin

### Storage

Host `Config` and `PluginSettings`: `controlPlaneUrl` (string, default `''`) and `keepVoiceOutside` (boolean, default `false`). All other fields are removed.

### `src/host/settings.ts`

`PluginSettings`, `DEFAULT_SETTINGS`; `engineConfig(cfg: VoiceConfig) → VoiceConfig` (a copy without `debug`); `selectedServices(cfg) → { sttServiceId, ttsServiceId }` (`''` where unset). `settingsFromVoiceConfig` and `voiceConfigFromSettings` are removed.

### `src/host/voice-config.ts` (new)

`createVoiceConfigSource({ controlPlaneUrl: () => string, fetch }) → { load, check, selected, clear, onChange }`.

- `ConfigAnswer` is `{ status: 200, config: VoiceConfig } | { status: 404 | 502, reason: string }`.
- `load()`: fetches `<url>/api/voice`. On 200 answers `engineConfig(body)` and records `selectedServices(body)`. Reasons: no URL `"No Banter server URL is set"` (404, nothing fetched); network failure `"No answer from <url>"`; non-2xx `"Banter answered <status>"` (both 502). A failed load leaves the recorded ids as they were.
- `check()`: the same fetch and answers, and never records.
- `selected()`: the recorded ids, or `null` before any successful load. `previous()`: the selection the current one replaced.
- `allowed()`: the ids the relays serve, the current selection's and the previous one's, so a page that started voice on the earlier selection keeps working until it reconfigures.
- `clear()`: forgets the recorded ids (the URL changed). A load that started before a clear, or that answers after a later load has recorded, records nothing.
- Fetches to Banter time out after 5 s, since the relays wait on them.
- `onChange(listener) → dispose`: called after a load that records ids different from those it replaces, the first successful load (from none) included.

### `src/host/index.ts`

- `GET /dsh-voice/voice` answers `load()`; `GET /dsh-voice/voice/check` answers `check()`; both gated like every plugin route. A 200 body is the config as JSON; a 404 or 502 body is `{ "reason": … }`.
- The relays serve the ids in `allowed()`. A speech or control request arriving while `selected()` is `null` runs `load()` first.
- STT upgrade routes are registered for the current and previous STT ids and re-registered from `onChange`; with nothing recorded there is none, and the page's first load registers it. A settings update that changes the URL clears the endpoints and the recorded ids and loads again; other settings updates leave them.
- `relay.ts` is unchanged.

### `src/client/config-feed.ts` (new)

`createConfigFeed({ origin, fetch, now }) → { reload, check, state, subscribe }`.

- `state()`: `{ config: VoiceConfig | null, loadedAt: number | null, error: string | null }`.
- `reload()`: fetches `<origin>/dsh-voice/voice`. Success sets `config`, `loadedAt = now()`, `error = null`. Failure keeps `config` and `loadedAt` and sets `error` to the answer's reason, or `"No answer from dsh"` when the host does not answer. A reload that was started earlier than the one whose result is already in place is discarded when it resolves, success or failure.
- In the runtime, a live reconfigure runs before the new config is put in the store, because the system reads the config it replaces to see whether the STT service changed. A config that lands while voice is starting waits for the start to end and then goes in the same way.
- After a URL write the settings page reloads the feed before it re-runs the checks.
- `check()`: fetches `<origin>/dsh-voice/voice/check` and resolves `{ ok: true } | { ok: false, reason }`; never changes `state()`.
- `subscribe(listener) → dispose`: called when `state()` changes.

### `src/client/runtime.ts`

- `RuntimeDeps` gains `feed`. `settings()` returns the stored `PluginSettings` from the form.
- The feed's config goes into the engine's store as the settings did: `setVoiceConfig`, `setVoiceSelection(resolveVoiceSelection(…))`, and `system.reconfigure` while live when the TTS service, model or STT service changed.
- `reload()` runs when the runtime is created, on `focus`, on `visibilitychange` to visible, and from `start`.
- `start(sessionId)`: with a config in the feed, calls `system.voiceOn` synchronously, then starts a reload it does not await. With no config ever loaded, does not call `voiceOn`, sets the notice to `"Can't reach Banter at <url>"` (or `"No Banter server URL is set"`) and starts a reload.
- `voice-button.tsx`: in the off state the button takes the error colour when the notice is set, and its tooltip prefers the notice.

### `src/client/server-url.ts` (new)

`normaliseServerUrl(input) → { ok: true, url } | { ok: false, problem }`: trims, removes trailing slashes, and accepts only an absolute `http:` or `https:` URL. An empty input is accepted as `''` (unset).

### Settings page

`settings-card.tsx` rewritten as the design's five sections. Autosave: a switch writes on change; the URL writes on blur or Enter after `normaliseServerUrl`, Escape restores the stored value. Each write is one `mutate([op], revision)`. Service rows use the feed's `check()`, `checkService` for the selected services, `navigator.permissions.query({ name: 'microphone' })` with `getUserMedia` for the Allow button, and the dashboard's page-support rules (copied: `isSecureContext`, `crossOriginIsolated`). `settings-controls.tsx` keeps `SelectField`; `RadioChoices`, `SliderField`, their CSS and the `@radix-ui/react-radio-group` and `@radix-ui/react-slider` dependencies go. `settings-model.ts` and its test are deleted.

### Install

`install-profile` fetches `<url>/api/voice` and fails with the existing message on a non-2xx, then writes `{ controlPlaneUrl }` as the row's config.

## 4. Tests

Written before the code. Names are the review artifact.

**Control plane** (`control/test/voice-defaults.test.ts`, "listening tuning"):
- a null field is removed from its section, and the section's other fields and curve stay, in the response and on disk
- removing a section's last field leaves the section as an empty object
- a field the dialog does not tune is refused even when sent as null
- a commit maximum removed in the same patch no longer limits the commit minimum

**Dashboard** (`dashboard/src/features/settings/voice-settings-model.test.ts`):
- the draft starts from the config's selection, STT service, take-over, mic samples, scope, chunking and tuning; take-over defaults to ask
- the model list holds only realtime models, and the voices are the selected model's
- changing the provider selects its first realtime model and that model's first voice; changing the model selects its first voice
- take-over is offered when the selected TTS provider or STT option declares sessions, and only then
- an unchanged draft, or one whose edits were reverted, builds no patch
- a speed edit sends the selection and nothing else
- the STT service, take-over, mic samples and scope are sent only when changed
- a global chunking edit sends only the changed global options
- a per-model edit sends only the touched model's entry, and resetting a stored preference sends null for it
- switching the model after a per-model edit keeps that edit for the first model
- a tuning edit sends only the changed field in its own section
- resetting a stored tuning field sends null for it; resetting one that was never stored sends nothing
- every tuning field carries the engine default it falls back to, inside its slider range
- provenance reports where each chunking value comes from, and which layers disagree

**Plugin** (`plugins/dsh/voice/`):
- `voice-config.test.ts`: a load answers the server's config without its debug section and records the selected STT and TTS services; a check answers the same and records nothing, keeping what an earlier load recorded; with no URL nothing is fetched and the answer is 404 with its reason; no answer and a non-2xx are 502 with their reasons, and keep what an earlier load recorded; a change of recorded services is reported once, and a load with the same services reports nothing
- `config-feed.test.ts`: a reload puts the fetched config in use with its load time; a failed reload keeps the config in use and reports the reason; a reload that resolves after a later one has landed does not replace it; a check reports reachability and leaves the config and error as they were
- `runtime.test.ts`: a start turns voice on before the reload it starts has answered; a start with no config ever loaded does not turn voice on and says Banter can't be reached; a reload that changes the selection while voice is live reconfigures it, and one that does not change it leaves it alone
- `server-url.test.ts`: surrounding space and trailing slashes are removed; anything other than an absolute http or https URL is refused with a problem; an empty value is accepted as unset
- `settings.test.ts` and `settings-model.test.ts` are deleted; the debug-stripping promise moves to `voice-config.test.ts`. `relay.test.ts` stays as it is.

Stays green: the dashboard suite, lint and typecheck; the plugin suite, lint and typecheck; the control tests; `voice-engine/src/boundary.test.ts`.
